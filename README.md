- 腕上提醒默认关闭：用户已提交 Wear Engine 服务申请，仍待审批，尚未配置有效 `client_id`。阶段 0 能力验证与阶段 1 真机验收均未完成，不能宣称该通道已接通。

- 正式提醒可由用户显式选择路线 A（Wear Engine 模板通知）或路线 B（手机普通通知经运动健康同步），同一事件只走当前路线，失败或超时不自动切换。普通通知自动提醒入口为「设置 → 腕上提醒 → 普通通知同步」，需主动开启并准备手机通知权限；亮屏守护时还需运动健康允许多设备提醒。操作和边界见 [docs/NotificationReminder.md](docs/NotificationReminder.md)。
- 无需等待 Wear Engine 审批的本地实测入口为「设置 → 手机通知同步测试」，支持立即发送或10秒后发送；用户已确认后者在手环上“显示并振动”。使用手机通知授权及运动健康现有同步设置，不直接控制手环马达、不启动守护或写统计。原理、实现、步骤和验证记录见 [docs/NotificationSyncTest.md](docs/NotificationSyncTest.md)。
- 评分、阈值、校准、灵敏度和 2/3/5 秒采样不变；腕上只消费前台真实守护中既有调度器确认的三级低分，要求新有效样本且本次分数仍 `<50`，不依赖手机振动开关或光效事件。
- 腕上使用独立于手机短振的 10 秒持久化冷却，A/B切换与同区域测试、正式提醒共用该冷却；手机双短振仍为60秒冷却，候选本地 TTL 最长 5 秒。失败、超时不重试，冷却、断连和恢复均不排队补发。B的单条通知请求关闭额外手机声音/振动，保留原短振；用户已确认改10秒前安装版的B单条测试在手环显示并振动，手机无额外反馈仍未确认。
- A须明确选一台设备，连接 `randomId` 仅存内存；B的同步目标由运动健康设置决定，本应用不能指定手环或检测其送达。测试由用户主动触发，并手动确认“收到并振动 / 只收到通知 / 没收到”。请求成功不等于实际显示或振动，测试与最多 100 条、最长 24 小时的本地诊断均不进入业务统计。
- 官方审批是 AGC 的 Wear Engine 服务准入，最小申请“设备基础信息 + 消息通知”，个人开发者可申请，不是手机 runtime 健康权限。真实 `client_id` 取得后才配置到 entry 模块 metadata，并匹配包名与签名；不填假值、不收集 secret。
- 应用版本为 `0.2.9 / 1000010`。Wear Engine 联调须先获服务批准，再核对运动健康版本、连接、勿扰与佩戴条件，经用户明确授权后开展。实现边界、审批依据与待验收项见 [docs/WearableReminder.md](docs/WearableReminder.md)。

## 0.2.8 三级低分提醒

- 手机前台真实守护时，低于 70/60/50 分分别独立持续确认至少 6 秒、两次有效采样，进入一级/二级/三级；沿用原有 2/3/5 秒抽帧。
- 一级为约 3 秒一次的淡红边缘呼吸光；二级约 2 秒并展示可靠纠正建议；三级复用二级视觉，允许两次 80ms 短振动，中间间隔 120ms。振动至少间隔 60 秒，暂停、切页、设置切换及隔离预览不重置冷却。
- 恢复使用两次连续采样达到 53/63/73 分的滞回阈值。人脸或双肩不可靠、多人关联不明确、数据过期、校准、停止和退后台会立即停止提醒并清理任务。
- 设置增加“低分边缘光”和“减少动态效果”，静态方案只显示细边框；沿用“短振动”开关。旧姿势提醒不再独立发声、振动或弹出强提醒，20 分钟休息提示保留为低打扰文案。
- 设置 → 开发者工具 → 低分提醒预览可分别查看三级效果，三级提供显式“试振动”；不启动相机，不修改真实分数、个人基线或统计。模拟采样与非守护诊断不新增正式记录。
- 用户反馈后，动态光效改为真实屏幕四边向中心连续透明渐隐，覆盖状态栏与底部导航区域，不再画预览卡硬红框；隔离预览使用同一全屏光效。减少动态效果仍用静态细框。
- 2026-10-15 已按用户确认的范围完成指定手机深浅色隔离预览、静态切换、交互取消和系统截图相册保存验收，测试后恢复原设置；真人守护端到端、实际振感/硬件精确时序及长期功耗仍未测。
- 自动测试、构建与设备验收分别记录在 [docs/LowScoreReminder.md](docs/LowScoreReminder.md)。

## 独立实时骨骼监看

- 「设置 → 实时骨骼监看」提供独立连续查看入口，无需开启守护，不评分、不更新基线或统计。

## 0.2.3 嘴部检测预览

- 支持人脸跟踪的设备使用本机 AR Engine 获取下颌张口强度和上下唇语义网格间隙，补上仅有五个人脸点时无法识别轻微分唇的问题。图像留在内存，不新增上传或照片落盘。
- 每次开始时以自然闭嘴状态校准。嘴唇间隙相对基线超过小幅噪声容差，或下颌张口信号达到阈值，嘴部单项立即扣分并同步影响总分；嘴唇回到基线范围后恢复。仍按用户选择的 2/3/5 秒抽样，不是逐视频帧实时提醒。

- 坐姿/抬头判定与阈值、提醒持续时间和冷却、统计口径均未修改。AR 相机数据通路有变化，不能把规则回归等同于识别效果完全不变。

## 当前实现

- 守护页：开始/结束守护、周期抽帧状态、三项指标、识别姿势图与建议、结束后的本次守护简短报告、三级低分提醒；识别姿势图会优先跟随当前可靠提醒类型。
- 统计页：今日均分、端正时长、提醒次数、今日问题分布、最近时段分布、最近记录；统计口径覆盖坐姿、抬头、嘴巴三项状态。
- 指南页：展示 `assets/posture` 的 12 组错误/正确姿势对比图。
- 设置页：沉浸光感 1–5 档、校准、标准/灵敏两档灵敏度、抽帧间隔、低分边缘光、减少动态效果、短振动、默认关闭的腕上提醒与单条测试、独立的手机普通通知同步测试、本地数据确认清空；开发者工具包含隔离提醒预览、真实/模拟检测切换确认、诊断详情、单次抽样，以及检测日志、精度校准、参数三个视图。
- UI：跟随系统深浅色、轻量表面、原生 Navigation 标题栏、底部导航和开关；API 26 使用标题沉浸材质和悬浮底栏，设置内容按钮使用同风格的分档表面。首页显示规则区分未开启、校准中、守护中和已结束状态，正式底栏保留守护、统计、指南、设置，浮窗入口暂时隐藏。
- 布局：API 26 悬浮 TabBar 的滚动内容预留 96vp 底部空间，旧系统底栏仍在页面流内；高影响操作进行中会锁住 Tab 切换。当前手机首页开始按钮和建议同屏，设置页末尾操作可滚动至底栏上方。
- 规则层：按《坐姿守护 App 算法设计与开发参考文档》和《坐姿守护 App Codex 开发规格书》实现 D1-D5 代理指标，并对外拆成 9 项提醒：
  挺起来、坐正、抬头、下巴收、头别歪、靠回椅背、屏幕抬高、嘴巴轻合、呼吸一下。
- 提醒层：由统一低分调度器按新采样时间确认等级、可靠问题文案和振动权限；三级沿用二级视觉，只有实际新视觉或成功发出的振动事件增加提醒次数，同次光效和振动只计一次，呼吸周期和采样刷新不重复计数。旧分项提醒规则文件仅保留文案及历史回归参考，不再接入正式反馈链路。
- 标准档对 D3 含胸/肩前扣更保守，普通电脑操作时的轻微前倾优先显示为“身体靠前”，避免过早判定“肩膀前扣”。
- 校准：每次启动采集 5 帧，手动校准采集 10 帧，通过原有人脸、双肩和头肩关键点质量检查后，按字段取中位数保存基线。原生嘴唇间隙额外要求至少 3 个可靠、低下颌强度且间隙跨度不超过 0.025 的样本，否则嘴部不计分；不沿用上次的嘴唇基线。失败、取消或离开应用均不覆盖旧姿态基线。界面显示 3 秒倒计时、完成百分比和结果；恢复默认基线前二次确认。
- 检测层：提供 `PostureSource` 抽象、`MockPostureSource`、`CoreVisionPostureSource`、`ARPostureSource`、`CoreVisionPostureDetector`。
- 真实检测：多人或多骨架入镜时按人脸置信度/面积、骨架关键点质量选择主用户；异常点位和人脸框会按未识别处理；释放检测器时逐项容错，避免相机重建后状态残留。
- 相机层：`CameraProbeService` 查询前置相机能力。支持设备优先用 AR Engine 原生相机帧，经 YUV/RGBA 转换、方向旋转后送入原 Core Vision 检测器；同次更新获取嘴部数据。首次启动不支持或失败时释放 AR，再退回隐藏 `XComponent` + `PhotoOutput.capture()` 通路，嘴部显示不可用。开始采样成功后不在会话中途切换相机几何。
- 相机准备：开始守护、结束守护、记录基线和单次抽样共用同一套权限申请、预览 surface 检查和相机预检流程；切换真实/模拟检测源前会二次确认；校准、手动抽样、守护启停、守护中抽帧间隔重启、清空数据和检测源切换进行中会锁住其他高影响操作，隐私与提醒开关也会跟随锁定。
- 页面生命周期：页面退出或应用进入后台时停止守护并释放相机、恢复主窗口；校准取消，后台不重新启动相机。长异步流程忽略过期结果，重复释放合并为同一次操作。
- 诊断显示：原“本机隐私模式”开关在开发者工具中改为“显示诊断详情”，只影响诊断文案，始终保持本机处理；模拟采样会明确显示不占用相机、不创建预览。
- 守护模式：开始守护时设置窗口常亮并压低窗口亮度，结束守护时恢复。
- 守护按钮：启动中、停止中和手动操作中都会进入锁定态，按钮文案、颜色和透明度保持一致。
- 权限：开始守护前会动态申请 `ohos.permission.CAMERA`。
- 存储：Preferences 本机保存设置和会话记录；读取旧数据时会清洗异常字段、异常时间戳和非数组记录，抽帧间隔归一化到 2/3/5 秒三档，并保持真实相机检测默认开启；隐私/开发诊断区域会显示本地数据读写状态。

默认设置使用真实相机检测；设置页仍可关闭为模拟采样，便于无相机环境验证 UI/规则。
真实链路已在真机验证 AR 相机帧与原有 JPEG 抽帧两条通路。Core Vision 继续负责骨架和头部角度，
AR Engine 负责原生嘴部信号。旧通路说明见 [docs/CoreVisionAdapter.md](docs/CoreVisionAdapter.md)，
当前能力边界见 [docs/Preview023.md](docs/Preview023.md)。
