# 坐直了

HarmonyOS NEXT / ArkTS 姿态守护应用 MVP。

## 0.2.2 开发预览

- 使用 DevEco Studio 26.0.0 / API 26 构建，最低兼容 API 23。底部导航改用原生 Tabs / BottomTabBarStyle，启用系统沉浸材质元数据；API 26 视觉仍待对应系统真机确认。
- 替换桌面图标、启动图标与首页标识，使用提供的 `assets/logo.png`，去除外围深色底。
- 每次开始守护先进行 3 秒准备 + 5 帧快速校准；设置中的手动校准保留 10 帧。移除逐帧额外延时，百分比按已完成采样更新，可取消，失败不覆盖基线。
- 设置增加浮窗入口，内容为分数、状态、采样时间及返回操作。当前安装包提供应用内子窗口预览，不宣称跨应用守护；API 26 系统闪控窗代码已接入，但权限配置尚未启用。离开应用停止相机检测，浮窗不显示过期实时分数。
- 修正嘴部能力误报：Core Vision 五点人脸没有上下唇位置，真实源的嘴部显示未启用，不再使用伪造的 `0.16` 正常值。真实分数暂按坐姿/抬头的原权重比例归一化；张嘴检测本身尚未实现。
- 首页只保留评分、三项等宽指标、守护操作、姿态建议和隐私摘要；校准位于设置，单次抽样、模拟检测、基线数值和相机诊断归入默认折叠的开发者工具。
- 相机故障时统一显示检测中断，不显示旧的实时分数和姿态建议；支持手动重新开启检测，原始错误仅在开发者诊断详情内展示。结束后的报告不再被旧错误文案覆盖。
- 指标卡、统计计数和基线展示改为响应式输入，连续采样时同步刷新，不再保留首次渲染的值。
- 坐姿/抬头判定、灵敏度、质量检查、提醒去抖/冷却和统计算法保持不变；本次明确改动校准时序与嘴部不可用时的评分处理。`scripts/verify-core.cjs` 对比已发布的 `fac06c8`，并单独验证新增行为。
- 使用与现有安装相同的包名和签名身份覆盖升级。开发签名安装包只适用于签名授权的测试设备。
- 构建与自动回归已通过，开发签名包已覆盖安装并启动；四个主页面、桌面图标、应用内浮窗拖动/关闭/退后台和校准取消已真机检查。实际校准耗时、张嘴识别和 API 26 专属效果仍未验收。详见 [docs/Preview022.md](docs/Preview022.md)。历史验证见 [docs/Preview26.md](docs/Preview26.md)。

## 当前实现

- 守护页：开始/结束守护、周期抽帧状态、三项指标、识别姿势图与建议、结束后的本次守护简短报告、前台轻提醒/强提醒；识别姿势图会优先跟随当前提醒类型。
- 统计页：今日均分、端正时长、提醒次数、今日问题分布、最近时段分布、最近记录；统计口径覆盖坐姿、抬头、嘴巴三项状态。
- 指南页：展示 `assets/posture` 的 12 组错误/正确姿势对比图。
- 设置页：校准、标准/灵敏两档灵敏度、抽帧间隔、轻提示音、短振动、本地数据确认清空；开发者工具包含真实/模拟检测切换确认、诊断详情、单次抽样，以及检测日志、精度校准、参数三个视图。
- UI：浅灰背景、轻量表面、原生底部导航和开关；首页显示规则区分未开启、校准中、守护中和已结束状态，正式底栏保留守护、统计、指南、设置。
- 布局：底部 TabBar 固定在页面流内，内容区滚动时不会被底栏覆盖；高影响操作进行中会锁住 Tab 切换。
- 规则层：按《坐姿守护 App 算法设计与开发参考文档》和《坐姿守护 App Codex 开发规格书》实现 D1-D5 代理指标，并对外拆成 9 项提醒：
  挺起来、坐正、抬头、下巴收、头别歪、靠回椅背、屏幕抬高、嘴巴轻合、呼吸一下。
- 提醒层：按 item 级提醒维护去抖、优先级和冷却；只有最终展示的提醒会消耗冷却，未展示的排队提醒继续等待；强提醒弹窗展示错误姿势到正确姿势的对比图，提醒反馈支持短振动和可选系统提示音，新提醒会先清理旧振动，关闭强提醒时也会停止当前反馈；轻提醒只在对应问题仍活跃时保留展示。
- 标准档对 D3 含胸/肩前扣更保守，普通电脑操作时的轻微前倾优先显示为“身体靠前”，避免过早判定“肩膀前扣”。
- 校准：每次启动采集 5 帧，手动校准采集 10 帧，通过原有人脸、双肩和头肩关键点质量检查后，按字段取中位数保存基线；真实源不更新嘴部基线。失败、取消或离开应用均不覆盖旧基线。界面显示 3 秒倒计时、完成百分比和结果；恢复默认基线前二次确认。
- 检测层：已提供 `PostureSource` 抽象、`MockPostureSource`、`CoreVisionPostureSource`、`CoreVisionPostureDetector`。
- 真实检测：多人或多骨架入镜时按人脸置信度/面积、骨架关键点质量选择主用户；异常点位和人脸框会按未识别处理；释放检测器时逐项容错，避免相机重建后状态残留。
- 相机层：已提供 `CameraProbeService`，开始守护时会查询摄像头、前置摄像头和预览/拍照能力；真实检测使用隐藏 `XComponent` 预览 surface + `PhotoOutput.capture()` 抽帧。
- 相机准备：开始守护、结束守护、记录基线和单次抽样共用同一套权限申请、预览 surface 检查和相机预检流程；切换真实/模拟检测源前会二次确认；校准、手动抽样、守护启停、守护中抽帧间隔重启、清空数据和检测源切换进行中会锁住其他高影响操作，隐私与提醒开关也会跟随锁定。
- 页面生命周期：页面退出或应用进入后台时停止守护并释放相机、恢复主窗口；校准取消，后台不重新启动相机。长异步流程忽略过期结果，重复释放合并为同一次操作。
- 诊断显示：原“本机隐私模式”开关在开发者工具中改为“显示诊断详情”，只影响诊断文案，始终保持本机处理；模拟采样会明确显示不占用相机、不创建预览。
- 守护模式：开始守护时设置窗口常亮并压低窗口亮度，结束守护时恢复。
- 守护按钮：启动中、停止中和手动操作中都会进入锁定态，按钮文案、颜色和透明度保持一致。
- 权限：开始守护前会动态申请 `ohos.permission.CAMERA`。
- 存储：Preferences 本机保存设置和会话记录；读取旧数据时会清洗异常字段、异常时间戳和非数组记录，抽帧间隔归一化到 2/3/5 秒三档，并保持真实相机检测默认开启；隐私/开发诊断区域会显示本地数据读写状态。

默认设置使用真实相机检测；设置页仍可关闭为模拟采样，便于无相机环境验证 UI/规则。
真实链路已在真机上验证：前置相机 JPEG 抽帧、`ImageSource` 读取源图尺寸、解码为 `PixelMap`，
再交给 Core Vision 骨架与人脸检测，结果写入守护页和统计页。实现细节见
[docs/CoreVisionAdapter.md](docs/CoreVisionAdapter.md)。

## 真机开发闭环

```bash
./scripts/start-phone-keepawake.sh
./scripts/install-run.sh
./scripts/keepawake-status.sh
```

- `start-phone-keepawake.sh` 会安装并加载 macOS LaunchAgent，每 480 秒用 `hdc uinput` 点击一次手机。
- `install-run.sh` 会构建、安装 signed HAP，并启动 `com.longxin.zuozhile/EntryAbility`。
- `keepawake-status.sh` 用于确认保活任务退出码和最近点击日志。

如果 DevEco Studio 重新生成签名，请确认 `build-profile.json5` 的 `products.default.signingConfig` 仍指向 `default`。
