# API 26 开发预览

更新日期：2026-09-22。版本：0.2.1 / versionCode 1000002。

## 配套环境

| 项目 | 配置 |
| --- | --- |
| DevEco Studio | 26.0.0.821 |
| 内置 HarmonyOS SDK | 26.0.0.105 Release / API 26 |
| targetSdkVersion | 26.0.0 |
| compatibleSdkVersion | 6.1.0(23) |
| 当前连接手机 | API 24 |

构建脚本直接使用 DevEco 安装目录中的 Hvigor、JBR 和 SDK，避免独立命令行工具版本混用。
签名材料继续由 DevEco 管理，不向文档、测试产物或日志复制签名密码。

## 界面与兼容

- 首页：紧凑评分、三个等宽指标、单一守护主按钮、识别建议、隐私摘要。
- 统计：没有采样时均分显示 `--`，无数据时段不绘制低分色柱；统计计算方法不变。
- 指南：保留全部 12 组姿态对比图。
- 设置：用户校准和提醒设置；开发者工具默认折叠，包含诊断、模拟源、抽样和调试视图。
- 设置中的声音、振动和诊断详情使用原生开关；检测源切换仍经二次确认。
- 底部导航使用系统图标，位于页面流中，不遮挡滚动内容。内容最大宽度 600vp，窄屏保持可滚动。
- `ImmersiveSurface` 通过 `deviceInfo.apiAvailable('26.0.0')` 隔离新系统材质调用；旧系统不创建 API 26 材质。
- 未开启和本轮尚未采样时显示待识别状态；首页保留相机权限、启动和采样失败信息。
- 三项均为 UNKNOWN 时，实时评分显示 `--`，提示保持入镜；单项未识别时不展示默认数值。
  这仅影响界面显示，不修改模型输出、记录内容、提醒条件或统计口径。
- 最新采样通过 ArkUI 状态驱动首帧刷新，避免指标停留在启动时的待识别分支。

## 核心保护

运行：

```bash
/Applications/DevEco-Studio.app/Contents/tools/node/bin/node scripts/verify-core.cjs
./scripts/verify-app.sh
```

回归参考提交为 `5f1e38f`。脚本比较八个核心模型/服务文件和十个页面采样、校准、提醒与会话方法，
并执行标准/灵敏两档、三种抽帧间隔下的 20,160 次姿态判断、2,520 次提醒决策以及校准和统计对比。
另覆盖未开启、等待首帧、过期帧、首帧到达、未识别、权限失败、结束报告的显示状态。
这是规则一致性和显示逻辑验证，不代替摄像头、设备性能或新系统视觉 SDK 输出的真机验证。

## 0.2.1 补充验证

- 连续采样暴露出三项指标卡保留初始参数的问题，顶部分数与卡片显示不一致。
  将按值传参的 Builder 替换为 `PostureMetricTile` 响应式组件，指标文字、数值、颜色均以 `@Prop` 同步。
  统计计数与基线展示组件的普通输入字段也改为 `@Prop`，不改源数据。
  依据 [ArkUI 父子单向同步说明](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides-V13/arkts-prop-V13)。
- 真机连续三次布局记录中，坐姿值依次为 231%、248%、261%，抬头值为 -2°、3°、-3°；
  随后卡片由“纠正/靠回椅背”更新为“正常/肩颈稳定”，顶部同步为“坐姿在线”。
  证明同一守护会话内文字、数值和状态持续更新，而非仅在首次入镜或切换页面时刷新。
  本机证据为 `artifacts/preview-2026-09-22/sample-{a,b,c}.json`。
- 恢复工作时，真机上出现 `PhotoOutput.capture` 错误码 `7400201`。原界面同时显示守护中、
  等待入镜和相机服务错误。手动停止并重新开启后恢复有效采样，三项指标和姿态建议均有更新。
- 界面现在区分检测中断与未入镜：错误状态隐藏旧实时分数、指标及姿态判断，提供手动重新开启入口。
  原始技术错误移至设置中的开发者诊断详情；已结束报告优先于历史错误文案。

  以及重启失败后的错误提示。不进行自动重试，也不宣称已修复相机服务错误的根因。
- 声音与振动开关经过双向切换验证，恢复为声音关闭、振动开启；覆盖安装后仍保留。
