# 独立实时骨骼监看

## 使用

1. 结束守护、校准或单次抽样。
2. 打开「设置 → 实时骨骼监看 → 打开实时监看」。入口独立于开发者工具。
3. 点击「开始实时监看」，按需允许相机权限。页面打开时不会自动占用相机。
4. 默认显示纯骨骼，可开启「相机画面」叠加同一检测帧，或切换镜像。
5. 点击「停止监看」或「返回」结束。进入后台也会停止，不在返回前台时自动恢复。

旧「开发者工具 → 骨骼监看」保留单帧诊断和守护间隔观察用途；新功能不是反复调用「采集一帧」。

## 连续更新与性能

- 使用前置相机的 `PreviewOutput → ImageReceiver` 连续预览流，只运行骨骼检测；不反复拍照，也不依赖 AR 嘴部检测或修改原守护检测链路。
- 需要设备支持前置 NV21/YUV420SP 预览、ImageReceiver 和 Core Vision 骨骼检测。不支持或图像布局不兼容时明确停止并显示原因，不假装为实时或切回单帧照片。
- 每次监看保持一个相机会话和一个骨骼模型实例。控制器串行等待采集、推理和可选编码完成后才获取下一帧，不创建并行推理队列。
- 目标刷新预算为最高约 10 FPS；页面显示实际完成帧率、每帧处理耗时和累计帧数，不把相机输出帧率当成模型帧率，不保证所有设备达到 10/30/60 FPS。
- 纯骨骼不编码照片，并复用 Canvas；相机叠加需额外 JPEG/Base64 编码，只使用对应同一帧的骨骼和图像，可能降低刷新速度。
- 只绘制可靠关节，不补造缺失或被遮挡的点；多人时仅展示最可靠的骨架，不进行身份跟踪。
- 超过 2 秒没有新结果时清除旧画面，避免将静止旧帧当作持续监看。帧龄和 FPS 使用单调运行时钟。

## 隔离与清理

- 只运行骨骼查看链路，不调用评分、校准、记录持久化、振动或通知；不改变守护的 2/3/5 秒采样设置、个人基线或真实/模拟源选择。
- 与守护、校准、单次抽样互斥；监看准备、运行、停止和弹层退出过程中阻止其他相机操作。旧诊断监看在独立监看期间失活。
- 取消立即清画面和调度任务；等待在途采集、推理或编码结束后释放相机和模型，再解除忙碌状态。不超时抢跑、不自动重启或补帧。
- 如果相机释放失败，保留占用锁并显示「重试释放相机」；未确认释放前不能开始新监看或守护，必要时退出并重启应用。
- 相机画面开关仅在本次页面内存中存在；关掉立即清除已有图像，丢弃开关变化前尚未完成的结果。返回后重新打开默认不显示相机图像。
- 不同监看会话使用独立代次，旧回调不能因重新开始而再次有效；发布时复制关键点和帧信息，不让界面修改检测源的数据。
- 不保存照片、视频或关键点文件，不上传图像。
